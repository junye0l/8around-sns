# PR 만들기

`AGENTS.md`가 규칙의 출처다. 이 문서는 그 규칙을 PR 만드는 절차로 옮긴 것이다.
규칙이 바뀌면 `AGENTS.md`가 이기고, 이 파일을 고쳐야 한다.

## 0. 먼저 멈추고 확인한다

```bash
git status --short && git branch --show-current && git log --oneline origin/main..HEAD
```

- **`main` 위라면 멈춘다.** 브랜치를 파야 하는데, 브랜치 생성·전환은 사용자 확인 대상이다 (규칙 7).
  이름을 제안하고 승인을 받는다: `타입/영문-케밥-케이스`
- **변경에 기능이 두 개 이상 섞였으면 멈춘다** (규칙 11). 어떻게 쪼갤지 제안하고 답을 기다린다
- `git diff`를 실제로 읽는다. 무엇이 바뀌었는지 모르는 채로 PR 본문을 쓰지 않는다

## 1. 검증

```bash
npm run verify
```

**실패하면 고치고 다시 돌린다.** 실패한 채로 커밋하지 않는다.
스키마를 건드렸다면 `npm run types:gen`을 돌렸는지 확인한다 (규칙 8).

## 2. 커밋

`AGENTS.md`의 커밋 컨벤션을 그대로 따른다.

```
타입: 한 줄 요약

왜 이렇게 했는지. 무엇을 했는지가 아니라.
```

- 타입: `feat` `fix` `refactor` `style` `chore` `docs` `test`
- 요약은 한국어, 마침표 없이, 50자 이내
- **되돌릴 수 있는 단위로 나눈다.** 성격이 다른 변경이 섞였으면 커밋을 쪼갠다
- 커밋 메시지 꼬리에 세션의 Co-Authored-By / Claude-Session 줄을 붙인다

## 3. 푸시

**푸시는 사용자 확인 대상이다** (규칙 7). 커밋까지 해두고 물어본다.

```bash
git push -u origin <브랜치>
```

## 4. PR 생성

`.github/PULL_REQUEST_TEMPLATE.md`의 항목을 **전부** 채운다. 항목을 지우지 않는다.
해당 없으면 "없음"이라고 쓴다.

| 항목 | 쓸 내용 |
|------|---------|
| 무엇을 | 기능 또는 UI 한두 줄 |
| 어떻게 | 구현 방법 + 핵심 파일 경로 |
| 왜 | 그 방법을 고른 이유. 근거는 `파일:줄` 또는 명령 출력 (규칙 4) |
| 트레이드오프 | 무엇을 포기했는지. **여기를 "없음"으로 채우기 전에 한 번 더 생각한다** |
| 참고사항 | 리뷰어가 알아야 할 것. 마이그레이션 적용 필요 여부 등 |
| 체크리스트 | 실제로 한 것만 체크한다. 안 한 건 비워두고 왜 안 했는지 적는다 |

```bash
gh pr create --title "<커밋과 같은 형식>" --body "$(cat <<'EOF'
...템플릿을 채운 본문...
EOF
)"
```

PR 본문 꼬리에 세션의 생성 표기 줄을 붙인다.

## 5. 보고

- PR 링크
- CI 상태 (`gh run list --limit 1`로 확인. 돌기 전이면 "아직 안 돌았다"고 쓴다)
- PR을 열면 Claude 자동 리뷰가 붙는다. **대응 절차는 `/pr-review` 스킬에 있다** — 여기서 다시 적지 않는다 (규칙 3)

## 하지 않는 것

- **머지하지 않는다.** 머지는 사용자가 한다
- 체크리스트를 실제로 확인하지 않고 체크하지 않는다 (규칙 5)
- 테스트가 깨진 채로 "아마 될 것"이라고 쓰지 않는다
- 리뷰 대응을 여기서 하지 않는다. `/pr-review`로 넘긴다

# 0018. 추천 위쪽 글쓰기는 모달을 연다

- 상태: 일부 대체됨 → [0019](0019-comment-compose-modal.md)
- 날짜: 2026-09-12

**어디가 바뀌었나.** "추천 위쪽 글쓰기는 모달을 연다"는 그대로다. 아래 `따라온 것`의
"댓글·답글 화면의 인라인 `Composer`는 그대로다"가 0019에서 뒤집혔다 — 댓글과 답글도
같은 모달에서 쓴다.

## 맥락

결정 0013이 글쓰기 진입점을 둘로 뒀다. 추천 위쪽의 인라인 입력칸과 레일에서 여는 모달이다.
둘 다 같은 `Composer`와 `createPostAction`을 썼지만, 입력을 받는 자리가 둘이라
글자수 상한 안내나 실패 처리처럼 입력에 붙는 것은 두 자리에서 같은 모양으로 맞춰야 했다.

사용자가 추천 위쪽 UI를 누르면 레일과 같은 모달이 열리게 하라고 지정했다.
레퍼런스(Threads)의 피드 위쪽 행도 입력칸이 아니라 모달을 여는 트리거다.

## 선택지

**A. 인라인 입력칸을 유지한다** — 결정 0013 그대로

- 피드를 보다가 화면 전환 없이 바로 쓴다
- 입력 자리가 둘이다. 입력에 붙는 변경은 두 자리에서 확인해야 한다. 사용자가 거부했다

**B. 줄 전체를 버튼 하나로 만들어 모달을 연다**

- 어디를 눌러도 열린다
- 버튼 안에 버튼을 넣을 수 없어 오른쪽 게시 버튼은 가짜가 된다. `Button`의 모양을
  버튼이 아닌 요소에 복사해야 한다 (규칙 2)

**C. 문구와 게시 버튼이 각각 모달 트리거다**

- 실제 버튼 둘이 같은 `Dialog`를 연다. `Button`을 그대로 쓴다
- 아바타만 눌러서는 열리지 않는다

## 결정

**C.** 사용자가 모달을 지정했고, 그 안에서 가짜 버튼을 만들지 않는 쪽이다.

모달은 `components/post/ComposeDialog.tsx`로 빼서 레일의 `ComposeButton`과 피드의
`ComposeRow`가 같이 쓴다. 입력을 받는 자리는 모달 하나다.

결정 0013의 "글쓰기 진입점이 둘이 됐다. 추천 화면 위쪽 입력칸은 그대로 두고"는 이 결정으로
사실이 아니게 됐다. 0013의 본 결정(radix 도입, 레일에 글쓰기 진입점)은 그대로다.

## 따라온 것

- 모달이 열리면 포커스가 첫 버튼(취소)이 아니라 textarea로 간다. 쓰려고 연 창이다
- 피드의 게시 트리거는 outline이다. 제출이 아니라 여는 버튼이라 채움을 쓰지 않는다
- 댓글·답글 화면의 인라인 `Composer`는 그대로다. 그 화면은 글 하나에 답을 다는 자리라
  전환 없이 쓰는 것이 맞고, 진입점도 하나뿐이다

# 0042. 제출은 렌더를 기다리지 않는 막이로 한 번만 보내고, 보낼 것이 없으면 버튼을 끈다

- 상태: 확정
- 날짜: 2026-09-14

## 맥락

화면 크리틱에서 빈 입력에도 전송 버튼이 눌린다는 지적이 나왔고, 사용자가 제출 버튼의 비활성과
중복 요청을 엄격하게 다루라고 했다.

브라우저에서 액션 요청을 세어 봤다. 서버가 검증에서 돌려보내는 입력을 써서 DB에는 쓰지 않았다.

- 보통 더블클릭은 요청 1번이다. 두 클릭 사이에 React가 다시 그려 `pending`이 켜진다
- 같은 틱 안의 클릭 두 번은 글쓰기, 댓글, 팔로우, 프로필 저장, 로그인 모두 요청 2번이었다.
  `pending`은 다음 렌더에야 켜지고, 그 사이 제출은 `useActionState`가 줄 세워 차례로 보낸다
- 로그인과 가입은 실패하면 입력칸이 전부 비었다. React가 함수 action이 끝나면 폼을 비운다

## 선택지

**중복을 어디서 막나**

- A. 클라이언트에서 렌더를 기다리지 않는 ref로 막는다. `hooks/useSubmitAction.ts` 하나를 폼 여섯이 쓴다
- B. 서버에서 멱등 키로 막는다. 폼마다 키를 싣고 테이블에 유일 제약을 둔다. 마이그레이션이 들고,
  같은 말을 두 번 쓰는 정상 요청과 구분하려면 키 수명까지 정해야 한다

**보낼 것이 없을 때**

- C. 진짜 `disabled`로 끈다. 비활성 모양이 `Button`에 이미 있고, 기본 버튼이 꺼져 있으면 Enter 암묵 제출도 일어나지 않는다
- D. `aria-disabled`로 두고 누름만 막는다. 진행 중(`loading`)이 이 방식인 이유는 누른 버튼이 꺼지면 포커스가 떨어져서다(결정 0012).
  입력이 비는 순간 포커스는 입력칸에 있으므로 여기서는 그 문제가 없다

## 결정

**A와 C.**

- 글쓰기, 댓글, 답글, 수정은 공백뿐이거나 처음 값과 같으면 끈다 (`components/ui/Composer.tsx`)
- 프로필 저장은 별명, 소개, 관심사, 사진 중 바뀐 것이 없으면 끈다. 별명을 비운 것은 끄지 않는다, 서버 문구가 이유를 말한다
- 로그인과 가입은 비어도 끄지 않는다. 비밀번호 관리자나 자동완성이 입력 이벤트 없이 칸을 채우면 state가 빈 채로 남아
  버튼이 꺼진 채 멈출 수 있다. 이 동작은 이 레포에서 재현해 보지 않았다. 비었을 때는 서버 문구가 칸마다 이유를 말한다
- 로그인과 가입 칸을 state로 들어 실패해도 쓰던 값이 남는다
- 좋아요는 그대로 둔다. 연달아 누르는 것이 의도된 토글이고 마지막 요청만 확정한다(결정 0021)

## 비용

- 요청을 직접 보내면 같은 글이 두 번 들어간다. 그건 글을 두 번 쓰는 것과 같아서 막지 않는다
- 로그인, 가입 비밀번호가 실패 뒤에도 칸에 남는다

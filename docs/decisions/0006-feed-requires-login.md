# 0006. 피드는 로그인해야 본다

- 상태: 확정
- 날짜: 2026-09-11

## 맥락

RLS는 게시글 읽기를 열어뒀다 — `"게시글은 누구나 본다" for select using (true)`
(`supabase/migrations/0001_init.sql:126-128`). 즉 DB는 익명 읽기를 허용한다.
공개로 갈지 막을지는 DB가 아니라 미들웨어에서만 갈린다.

동시에 `docs/PLAN.md` §3의 "비로그인 보호 라우트 차단"이 계속 미뤄져 있었다.
막을 화면이 없었기 때문이다. 피드가 들어오면서 처음으로 막을 것이 생긴다.

## 선택지

**A. 공개 피드** — `/`를 익명에게도 연다
- 배포 URL을 열면 바로 내용이 보인다
- 비로그인용 빈 상태와 "가입하고 글 쓰기" 유도가 따로 필요하다
- 작성칸을 피드 위에 놓을 수 없다. 비로그인에게는 감추거나 눌렀을 때 보내야 한다
- 이번에도 보호할 라우트가 없어 §3 항목이 또 미뤄진다

**B. 로그인 전용 피드** — `/`를 막고 `/login`으로 보낸다
- 화면 하나가 상태 하나만 갖는다. 작성칸을 피드 맨 위에 그냥 둔다
- §3 "보호 라우트 차단"이 이번에 실제로 닫힌다
- 익명 방문자는 배포 URL에서 로그인 화면부터 만난다

## 결정

**B.**

## 이유

심사 동선(`docs/PLAN.md` §9)이 가입 → 로그인 → 글 작성 순서다. 어차피 로그인 상태로 흐른다.
A를 고르면 그 동선에서 한 번도 쓰이지 않을 비로그인 화면 상태를 만들고 유지해야 한다.

B는 "허용 목록에 없으면 막는다"로 쓸 수 있어 화면이 늘어도 목록을 고칠 일이 없다
(`lib/utils/auth-route.ts`). A는 막을 경로를 하나씩 더해야 하고, 빠뜨린 화면이 조용히 열린다.

## 비용

- 익명 방문자가 내용을 못 본다. SNS로서는 유입 경로 하나를 버리는 것이다
- 되돌리는 비용은 작다. `PUBLIC_PATHS`에 `/`를 더하고 비로그인 빈 상태를 만들면 된다.
  RLS는 이미 열려 있어 마이그레이션이 필요 없다

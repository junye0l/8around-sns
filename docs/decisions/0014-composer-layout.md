# 0014. 글자수 카운터를 버리고 입력칸 높이를 고정한다

- 상태: 일부 대체됨 → [0043](0043-soft-surface.md) (버튼 60x36, 빈 입력 비활성)
- 날짜: 2026-09-12

## 맥락

입력칸을 누르면 두 가지가 동시에 일어났다. `rows`가 1에서 3으로 늘고, 없던 글자수
카운터 줄이 생겼다. 둘 다 아래 내용을 밀어낸다. 추천 화면에서는 첫 게시글이,
모달에서는 버튼이 움직였다.

카운터는 상한이 가까워졌을 때만 쓸모가 있는데, 그 순간을 위해 입력할 때마다
자리를 차지하고 손댈 때마다 화면을 민다.

## 선택지

**A. 카운터 자리를 항상 비워둔다** — 접혀 있을 때도 높이를 차지한다

- 시프트가 사라진다
- 아무것도 없는 줄이 입력칸 아래에 늘 깔린다. 추천 화면 첫 칸이 그만큼 커진다

**B. 카운터를 없앤다**

- 시프트가 사라지고 줄도 안 생긴다
- 상한에 닿았을 때 왜 안 써지는지 알 단서가 `maxLength`의 무반응뿐이다

**C. 상한 근처에서만 보여준다** — 남은 글자가 적을 때만 나타난다

- 평소엔 안 보이고 필요할 때만 보인다
- 나타나는 그 순간이 곧 시프트다. 문제를 드물게 만들 뿐 없애지 못한다

## 결정

**B.** 사용자가 지정했다.

높이도 같이 고정했다. 접었다 펴는 것 자체가 같은 종류의 밀림이라, 카운터만 없애면
절반만 고친 것이 된다. `rows`는 3으로 고정이다.

상한을 넘겨 쓰는 일은 드물다 — 게시글 2000자, 댓글 1000자다
(`supabase/migrations/0001_init.sql:60`, `:83`). 그 드문 경우를 위해 늘 자리를
차지하는 쪽이 비싸다고 봤다.

## 따라온 것

- **버튼이 60x36에 문구 "게시"가 됐다.** `docs/DESIGN.md`의 웹 버튼 40 또는 46px
  어디에도 없는 값이고 사용자가 지정했다. 문서 자체의 Application priority가
  "1. Direct user instructions"를 맨 위에 두므로 규칙 3보다 지시가 앞선다.
  `Button`에 `size` 변형으로 넣었고 기존 큰 버튼(로그인, 가입하기)은 그대로다.
  결정 0009의 `남은 칸`에 있는 "기본 버튼 높이 40 대 46"은 여전히 미정이다
- **`pendingLabel`이 사라졌다.** 폭이 60px 고정이라 "올리는 중" 같은 문구가 안 들어간다.
  진행 중 표시는 `aria-busy`가 칠하는 회색과 커서가 맡는다 (결정 0012).
  `docs/DESIGN.md`가 요구하는 "preserve width while loading"은 폭 고정이 그대로 만족한다
- **제어 컴포넌트는 그대로 둔다.** 처음에는 카운터가 없어졌으니 `content` 상태도
  필요 없다고 보고 `key`로 갈아탔는데, 그 상태는 카운터가 아니라 **실패했을 때
  초안을 지키려고** 있던 것이었다. React 19는 함수 action이 끝나면 폼을 자동으로
  비우므로, 제어하지 않으면 실패해도 쓰던 글이 날아간다.
  `result.ok`에서 뽑은 key는 값이 성공·실패 사이를 오갈 때만 바뀌어서 연속 성공 때
  두 번째 글이 안 비워지고, 성공 뒤의 실패가 오히려 초안을 지웠다.
  PR #21 리뷰가 잡았고 원래 방식으로 되돌렸다. `opened` 상태만 없앴다
- **빈 입력일 때 버튼을 비활성으로 두지 않는다.** `required`가 막는다. 덤으로
  결정 0012가 남겼던 "비활성 버튼 글자 2.47:1이라 안 읽힌다"가 이 화면에서 사라졌다
- **아이콘 자리를 만들지 않았다.** 레퍼런스에는 이미지, GIF, 투표, 위치가 있지만
  전부 범위 밖이다. 누를 수 없는 아이콘을 세워두지 않는다
- **모달과 추천 피드가 같은 모양이다.** `Composer` 하나를 고쳐서 둘 다 따라왔다 (규칙 2)

## 남은 칸

- **상한에 닿았을 때 무엇으로 알리나.** 지금은 `maxLength`가 조용히 막는다.
  실제로 부딪히는 사람이 보이면 그때 정한다. 카운터를 되살리는 것 말고 다른 수단이어야 한다

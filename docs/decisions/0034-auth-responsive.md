# 0034. 인증 화면의 건너가는 줄을 글자로 잇고, 모바일은 로고를 가운데에 둔다

- 상태: 일부 대체됨 → [0043](0043-soft-surface.md), [0046](0046-auth-switch-primary.md)
- 날짜: 2026-09-14
- 대체: [0027](0027-auth-page-layout.md)의 "건너가는 줄은 문구와 outline 버튼", "가입" 문구

## 맥락

결정 0033으로 로그인 뒤 화면이 768px 미만에서 하단 탭바로 바뀌었다. 로그인, 회원가입 화면은
고정 폭이 없어 가로 스크롤은 없었지만 폼이 화면 세로 가운데에 떠 있어 모바일 키보드가 올라오면 밀렸다.
아티팩트 시안을 보고 사용자가 세 가지를 지시했다. 건너가는 줄을 버튼이 아니라 색이 다른 글자 두 개로
가로로 잇는다, "가입"을 "회원가입"으로 부른다, 안내 문구를 "30자까지 가능해요", "6자 이상, 특수문자도
가능해요"처럼 허용 범위로 쓴다.

## 선택지

**모바일 로고 자리**

- A. 위 가운데. 로그인 뒤 모바일 화면에는 로고가 없어 이어 받을 자리가 없다
- B. 지금처럼 왼쪽 위. 결정 0027의 "로그인 전후로 로고가 같은 자리"는 넓은 폭에서만 성립한다

**모바일에서 건너가는 줄의 자리**

- A. 화면 바닥 가운데. 엄지가 닿고 Threads 앱과 같다
- B. 폼 바로 아래. 넓은 폭과 같은 자리다

## 결정

로고 A, 자리 A. 사용자가 골랐다.

같이 정한 값:

- **건너가는 줄은 `fg-muted` 문구와 `fg` 600 글자 버튼.** 파랑은 포커스 링에만 쓴다(결정 0015)
- **글자 버튼의 누를 자리는 `-m-1 p-1`로 넓힌다.** `ContentCard` 이름 링크와 같은 방법이다
- **넓은 폭은 `hairline` 선 아래 왼쪽 정렬을 그대로 둔다**
- **별명 힌트에서 "다른 사람과 겹치지 않게"를 뺀다.** 겹치면 제출 때 에러 문구가 알린다(`lib/services/auth.ts:128`)
- **"특수문자도 가능해요"는 사실이다.** 비밀번호는 6자 이상만 본다(`lib/services/auth.ts:13`, `supabase/config.toml:184`)

## 비용

- 결정 0027이 버튼으로 바꾼 이유였던 누를 자리가 다시 작아진다. 40px에서 약 29px이다
- "이미 가입한 이메일이에요" 같은 에러 문장은 "가입"을 그대로 쓴다. 화면 이름만 "회원가입"이다

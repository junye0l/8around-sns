# 0033. 768px 하나로 나누고, 좁으면 레일을 아래 탭바로 내린다

- 상태: 일부 대체됨 → [0041](0041-soft-surface.md)
- 날짜: 2026-09-14

## 맥락

결정 0015가 뼈대의 최소 폭을 824px(`min-w-206`)로 두어, 태블릿과 모바일에서 화면이
가로로 스크롤됐다. 사용자가 태블릿은 PC와 같은 뼈대에 가로 스크롤만 없애고, 모바일은
Threads처럼 레일을 아래로 내리라고 요청했다. 시안을 아티팩트로 먼저 보고 확인받았다.

## 선택지

**모바일 윗줄**

- A. 화면 제목을 왼쪽에, 더 보기를 오른쪽에 둔다. 상세 화면의 뒤로 버튼과 한 모양이다
- B. Threads처럼 가운데 로고만 둔다. 지금 어느 탭인지는 탭바 색으로만 안다.
  상세 화면은 어차피 뒤로 버튼과 제목이 필요해 윗줄이 두 벌이 된다

**경계**

- A. Tailwind 기본 `md`(768px) 하나. 태블릿과 PC는 코드가 같다
- B. 태블릿 전용 경계를 하나 더 둔다. 태블릿이 PC와 같은 모양이라 나눌 것이 없다

## 결정

윗줄 A, 경계 A. 사용자가 골랐다.

같이 정한 값:

- **최소 폭을 지우고 좌우 76px(`px-19`)을 비운다.** 레일 자리만큼 비우면 겹치지 않고
  컬럼이 남은 폭으로 줄어든다. 1280px에서는 결과가 전과 같다
- **탭바 높이 64px(`h-16`), 위 hairline 1px.** 그림자를 쓰지 않는다. 항목 순서는 레일과 같다
- **더 보기는 모바일에서 제목줄 오른쪽으로 옮긴다.** 탭바에 여섯째 칸을 만들지 않는다
- **카드 안 좌우 패딩은 모바일 16px(`px-4`), 넓으면 24px(`px-6`).** 테두리 없는 흰 면에서 24px은 본문 폭을 너무 먹는다
- **제목 크기는 모바일에서도 `text-title`(24px).** 문서에 20px 토큰이 없다

## 비용

- 카드 안 줄을 그리는 컴포넌트 여럿이 `px-4 md:px-6`을 따로 가진다. 패딩을 바꾸면 전부 고친다
- iOS 홈 인디케이터 영역(safe area)을 비우지 않았다. 임의 값(`env()`)이 필요해서다

## 남은 칸

- 로그인, 회원가입 화면의 좁은 폭. 이 두 화면은 `PageShell`을 쓰지 않는다

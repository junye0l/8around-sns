# 0017. 글 입력칸에는 포커스 링을 두지 않는다

- 상태: 확정
- 날짜: 2026-09-12

## 맥락

`Composer`의 textarea를 누르면 결정 0010의 파랑 2px 링이 입력칸 사방에 그려졌다.
버튼과 달리 입력칸은 테두리가 없는 면이라, 링이 곧 상자가 된다. 사용자가 이것을
나쁜 UI로 지목했다. 레퍼런스(Threads)의 글쓰기 모달은 입력면에 테두리도 링도 없고,
캐럿과 placeholder만이 포커스를 말한다.

결정 0010은 버튼의 keyboard focus 상태를 채우며 정한 값이다. 입력칸은 다르다.
포커스가 들어오면 캐럿이 깜빡이고 placeholder가 보이므로 상태가 이미 드러난다.
`TextField`(가입·로그인)는 처음부터 `outline-none`이었고 `focus:border-fg`로 테두리
색만 바꾼다. 텍스트 입력에는 이미 링을 쓰지 않고 있었다.

## 선택지

**A. 결정 0010 그대로 둔다** — 파랑 2px 링

- 모든 포커스 가능한 요소가 같은 신호를 낸다
- 입력칸에는 상자가 없으므로 링이 상자가 되고 캐럿과 신호가 겹친다. 사용자가 거부했다

**B. 얇은 `hairline` 링** — 1px, 중립색

- 링은 남되 덜 튄다
- `hairline`은 흰 바탕에서 1.23:1이라 있으나 마나다 (결정 0012). 있는데 안 보이는 것은
  없는 것보다 나쁘다

**C. 링을 두지 않는다** — `outline-none`

- 캐럿과 placeholder가 포커스를 말한다. `TextField`와 같은 방식이다
- 규칙 10의 keyboard focus 상태를 링 대신 캐럿이 채운다는 판단이 필요하다

## 결정

**C.** 사용자가 링을 지목했고, 텍스트 입력에서 캐럿은 링보다 먼저 있는 신호다.

결정 0010은 그대로다. 버튼, 링크, 메뉴 항목처럼 캐럿이 없는 요소는 여전히 파랑 링을 쓴다.
이 결정은 텍스트 입력(`Composer`, `TextField`)에만 적용된다.

## 따라온 것

- **버튼이 입력칸 오른쪽 아래로 붙었다.** 이름·입력 칸 아래 한 줄을 차지하던 버튼을
  form의 flex 행으로 올리고 `self-end`로 바닥에 맞췄다. 한 줄이 줄고 `rows`는 3 그대로라
  결정 0014의 고정 높이는 유지된다. 레퍼런스의 인라인 행(아바타, placeholder, 오른쪽 버튼)에
  가까워진다
- **모달 제목줄의 구분선을 뺐다.** 레퍼런스의 모달은 제목 아래 선이 없다
  (로그아웃 상태의 threads.com에서 본 모달로 확인했다. 글쓰기 모달 자체는 로그인이
  필요해 보지 못했다)
- 인라인 행의 버튼을 outline으로 바꾸지 않았다. 레퍼런스의 인라인 버튼은 모달을 여는
  가짜 버튼이라 흐리지만, 우리 것은 실제 제출이다. `Composer`에 변형 prop을 더하지 않는다

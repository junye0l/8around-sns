# 0036. 관심사는 profiles의 text[] 컬럼에 두고, 프로필 편집 모달에서만 넣는다

- 상태: 확정
- 날짜: 2026-09-14

## 맥락

사용자가 Threads 프로필처럼 관심사를 붙이고 싶다고 요청했다. 요구 기능 6개 밖이지만 사용자 요청이라 범위에 넣는다.
아티팩트 시안을 보고 사용자가 정한 값은 최대 3개, 한 개에 2글자, 입력은 편집 모달 안이다.
관심사는 보여주기만 한다. 눌러서 같은 관심사를 모아 보는 것은 검색이라 범위 밖이다.

## 선택지

**저장 방식**

- A. `profiles.interests text[]`에 개수와 원소 CHECK. 한 사람의 관심사를 한 번에 읽고 쓴다. 기존 수정 정책이 그대로 덮는다
- B. `profile_interests` 테이블. 관심사로 사람을 거꾸로 찾을 때 필요한데, 그것은 검색이다. 테이블, RLS 정책, 조인이 늘어난다

**입력 자리**

- A. 프로필 편집 모달 안의 입력칸, Enter와 추가 버튼. 입력은 모달 한 곳에서만 받는다(결정 0019)
- B. 프로필 화면의 `+` 칩. 누르는 횟수는 줄지만 입력 자리가 둘이 된다

**글자 수 기준**

- A. 코드 포인트. DB `char_length`와 같다. 앱은 `[...s].length`로 센다
- B. UTF-16 길이(`.length`). 이모지 하나가 2로 세어져 DB와 어긋난다

## 결정

저장 A, 입력 A, 글자 수 A. 저장과 입력은 사용자가 골랐다.

같이 정한 값:

- **원소 검사는 `profile_interests_valid` 함수로 감싼다.** CHECK에는 서브쿼리를 못 쓴다. 앞뒤 공백, 빈 값, 중복도 DB가 막는다
- **서버는 `lib/utils/interests.ts`의 `interestsSchema`로 한 번 더 본다.** 문자열 배열이 아니면 거절하고, 다듬어서 빈 값과 중복을 뺀 뒤 개수와 글자 수를 본다. 에러는 관심사 칸에 붙는다
- **상한 3과 2는 `lib/utils/content-limits.ts`에 둔다.** 별명, 소개 상한과 같은 자리다. 입력칸이 import하므로 zod와 같은 파일에 두지 않는다
- **폼에는 칩마다 `name="interests"` hidden input으로 싣고, 액션이 `getAll`로 모은다.** 다 지우면 빈 배열로 저장된다
- **프로필 화면에서는 소개 아래 12px에 칩 줄이 선다.** 비면 줄이 없다
- **칩은 `hairline` 테두리와 `fg` 글자다.** 시안의 `#4e5968`(body)은 색 토큰이 없어서 쓰지 않는다. `fg-muted`는 흰 바탕 글자 대비가 3.04:1이라 본문 글자로 쓰지 않는다. 누를 수 없고 파랑을 쓰지 않는다
- **3개가 차거나 저장 중이면 입력칸은 readOnly, 추가 버튼은 aria-disabled.** 진짜 disabled는 포커스를 body로 떨어뜨린다(결정 0012). 한글 조합을 끝내는 Enter는 넣지 않는다

## 비용

- 관심사로 사람을 찾는 기능이 생기면 테이블로 옮기는 마이그레이션이 필요하다
- `profile_interests_valid`가 public 스키마에 있어 PostgREST RPC로도 불린다. 입력을 검사해 참거짓만 돌려준다

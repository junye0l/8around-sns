# 0019. 댓글도 모달에서 쓰고, 답글이 둘 이상이면 접는다

- 상태: 확정
- 날짜: 2026-09-12

## 맥락

사용자가 레퍼런스(Threads)의 게시글 상세 화면을 놓고 두 가지를 지정했다.

- 댓글 입력이 인라인 입력칸이 아니라 아바타와 문구 한 줄이고, 누르면 창이 열린다
- 답글이 여러 개면 펴지 않고, 겹친 아바타와 "답글 보기" 한 줄로 접는다

결정 0018은 추천 화면의 글쓰기를 모달로 옮기면서 "댓글·답글 화면의 인라인 `Composer`는
그대로다"라고 적었다. 첫 번째 지정이 그 줄을 사실이 아니게 만든다.

결정 0008은 답글을 게시글 화면에서 같이 보여주기로 했다. 그때는 답글이 몇 개든 전부 폈다.

## 선택지

### 가. 댓글 입력

**A. 게시글 상세만 모달로 바꾸고 답글 화면은 인라인으로 둔다**

- 답글 화면은 답을 달러 들어온 자리라 한 번 덜 누른다
- 같은 댓글 입력이 두 모양이다. 입력에 붙는 변경을 두 자리에서 확인해야 한다

**B. 두 화면 다 모달로 바꾼다**

- 입력을 받는 자리가 앱 전체에서 모달 하나다 (규칙 2)
- 답글 화면에서 한 번 더 눌러야 쓴다

### 나. 답글 접기

**C. 지금처럼 항상 편다** — 결정 0008 그대로. 사용자가 거부했다

**D. 답글이 있으면 항상 접는다**

- 규칙이 단순하다. 게시글 화면이 댓글 목록으로만 읽힌다
- 답글 하나짜리 대화가 한 줄 더 눌러야 보이는 것으로 바뀐다. 0008이 지키려던 "대화가
  끊기지 않는다"를 가장 흔한 경우에서 잃는다

**E. 둘 이상일 때만 접는다**

- 하나짜리는 그대로 이어 보인다. 목록이 길어지는 것은 여러 개일 때뿐이다
- 경계가 하나 생긴다. 1과 2가 다르게 보인다

## 결정

**B와 E.**

B는 사용자가 게시글 상세를 모달로 지정한 이상 답글 화면만 인라인으로 남기면 같은 입력이
두 모양이 되기 때문이다. 모달과 입력칸은 `components/ui/ComposeDialog.tsx` 하나이고,
액션·제목·문구·버튼 이름·상한·숨은 입력을 밖에서 받는다. 여는 한 줄은
`components/ui/ComposeRow.tsx`로, 추천의 글쓰기와 댓글·답글이 같이 쓴다.
글과 댓글이 같이 쓰므로 `components/post/`에서 `components/ui/`로 옮겼다.

E는 사용자가 지정한 값이고, 0008이 지키려던 것을 하나짜리에서 그대로 남기기 때문이다.

결정 0018의 "댓글·답글 화면의 인라인 `Composer`는 그대로다"는 이 결정으로 사실이 아니게
됐다. 0018의 본 결정(추천 위쪽은 모달, 트리거는 진짜 버튼 둘)은 그대로다.
0008의 "답글을 게시글 화면에서 본다"도 그대로다 — 하나일 때는 펴고, 둘 이상이면 들어가는 길만 남는다.

## 따라온 것

- 게시글 상세의 문구는 `<글쓴이>님에게 답글 남기기`다. 답글 화면이 쓰던 말투를 그대로 쓴다
- 접힌 줄의 아바타는 답글을 쓴 사람 셋까지고, 같은 사람은 한 번만 센다.
  원끼리 겹치는 경계는 카드 바탕색 테두리(`ring-canvas`)가 낸다. 그림자를 쓰지 않는다
- 아바타는 `aria-hidden`이라(`components/ui/Avatar.tsx`) 읽히는 것은 "답글 보기" 링크 하나다
- 부모 댓글의 `CommentCount`를 그대로 둔다. 답글이 0개, 1개일 때도 들어가는 길은 그것뿐이고,
  레퍼런스도 아이콘 줄과 "답글 보기"를 같이 둔다

# 0013. 드롭다운과 모달은 radix에서 가져오고, 글쓰기 진입점을 레일에 둔다

- 상태: 확정
- 날짜: 2026-09-12

## 맥락

레일에 항목이 셋뿐이었고 로그아웃이 맨 아래에 그냥 나와 있었다. 설정이 늘어날 자리가
없고, 글을 쓰려면 추천 화면으로 돌아가야 했다. 레퍼런스(Threads)처럼
`추천 / 새로운 게시글 / 프로필 / 팔로잉`을 세우고 하단에 "더 보기"를 두기로 했다.

둘 다 포커스와 키보드를 직접 다뤄야 하는 것이다. `AGENTS.md` 스타일 절이 그런 것은
직접 만들지 말고 shadcn 소스를 가져오라고 한다.

## 선택지

**A. 네이티브 `popover` 속성으로 드롭다운을 만든다**

- 새 의존성이 0개다. Esc 닫기와 바깥 클릭 닫기를 브라우저가 준다
- 화살표 이동과 타입어헤드는 없다. 항목이 로그아웃 하나뿐인 지금은 문제가 아니지만
  설정이 쌓이면 직접 만들게 된다 — `AGENTS.md`가 막은 바로 그 일이다
- 모달은 여전히 따로 풀어야 한다

**B. shadcn `DropdownMenu`와 `Dialog`를 가져온다** — radix 위에 우리 토큰을 입힌다

- 화살표 이동, 타입어헤드, 포커스 가두기, 포커스 복귀, 스크롤 잠금이 다 들어 있다
- `@radix-ui/react-dropdown-menu`, `@radix-ui/react-dialog` 둘이 붙고 전이 의존성까지
  39개가 설치된다. 빌드 산출물에서 radix 청크가 **31.7KB gz**로 잡혔다
  (`.next/static/chunks`에서 gzip으로 직접 측정). `SideNav`가 모든 라우트에 서므로
  이 비용은 전 라우트에 걸린다

## 결정

**B.** 사용자가 지정했다.

비용을 알고 고른 것이다. 감사(결정 0012 참고)가 지적한 tailwind-merge 9.3KB의 세 배가
넘지만, 설정 항목이 쌓일 자리를 손으로 만들지 않는 쪽을 택했다.

## 따라온 것

- **글쓰기 진입점이 둘이 됐다.** 추천 화면 위쪽 입력칸은 그대로 두고, 레일에서 여는
  모달을 더했다. 둘 다 같은 `Composer`와 같은 `createPostAction`을 쓴다 (규칙 2).
  앞의 것은 피드를 보다가 바로 쓰는 자리고, 뒤의 것은 어디서든 부르는 자리다
- `Composer`에 `onSuccess`가 생겼다. 모달이 닫히려면 저장 성공을 알아야 한다
- **`SideNav`의 prop이 `username`에서 `profile`로 바뀌었다.** 모달의 아바타가
  `display_name`을 쓰는데 별명만으로는 만들 수 없다. 호출부 일곱 곳을 같이 고쳤다
- **열고 닫는 애니메이션은 없다.** `docs/PLAN.md`가 애니메이션을 UI가 다 선 뒤로
  미뤄뒀고, radix의 `data-state`에 붙이려면 임의 값 변형이 필요해 하네스에도 걸린다
- **로그아웃만 빨강이다.** 메뉴에서 되돌리기 어려운 유일한 항목이다. 레퍼런스도 같다
- 그림자를 쓰지 않으므로 떠 있는 면도 `border-hairline` 1px로만 분리한다.
  오버레이는 `bg-fg/40`이다 — 새 색을 만들지 않고 기존 토큰의 불투명도만 낮췄다

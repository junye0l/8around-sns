# 0004. 가입·로그인을 한 화면에 놓고 미끄러뜨린다

- 상태: 대체됨 → 0016 (슬라이드를 걷어냈다, `replaceState` 두 라우트는 그대로다)
- 날짜: 2026-09-11

## 맥락

가입 화면이 토큰만으로 만들어져 실제 서비스처럼 보이지 않았다.
좌우 2단 카드에 오버레이가 미끄러지는 레퍼런스를 기준으로 다시 짜기로 했다.

슬라이드는 **두 폼이 한 DOM에 동시에** 있어야 한다. 라우트를 갈아타면 컴포넌트가
다시 마운트되어 전환이 끊긴다.

## 선택지

**A. 라우트 2개 + 링크 전환 (슬라이드 없음)**
- URL 유지. 추가 JS 0
- 레퍼런스의 느낌이 사라진다

**B. 한 라우트에 두 폼 + 슬라이드**
- 레퍼런스 그대로
- `/login`이 없어진다. 비로그인으로 보호 라우트에 왔을 때 보낼 곳이 애매해진다

**C. 라우트 2개 + 한 컴포넌트 + `replaceState`**
- 두 URL이 살아 있고 슬라이드도 된다
- 토글 후 주소와 화면을 직접 맞춰야 한다

## 결정

**C.** `/signup`과 `/login`이 같은 `AuthPanels`를 시작 면만 다르게 렌더하고,
토글은 라우트 이동 없이 `history.replaceState`로 주소만 바꾼다.

## 이유

URL을 잃는 값이 슬라이드보다 비쌌다. `/login`이 있어야 미들웨어가 보호 라우트에서
보낼 곳이 생기고(`docs/PLAN.md` §3) 링크 공유도 된다. C는 그 둘을 다 지킨다.

리소스와 보안은 판단 근거가 아니었다 — 슬라이드는 `transform`/`opacity`만 바꿔 합성만 일어나고,
두 폼이 한 페이지에 있어도 검증은 서버에서 다시 한다(AGENTS.md 규칙 9).

## 비용 — 슬라이드가 실제로 만든 세 가지

1. **접근성** — 덮인 폼이 Tab과 스크린리더에 그대로 잡힌다 → `inert`로 끈다
2. **URL** — 위의 `replaceState`
3. **자동완성** — 비밀번호 칸이 둘이라 `new-password` / `current-password`를 각각 붙였다

모바일(<md)에서는 슬라이드하지 않는다. 400px에 2단은 읽히지 않는다(`docs/DESIGN.md` §5).

## 함께 어긴 규칙

슬라이드가 가입과 로그인을 한 화면으로 묶어서, 이 PR이 `docs/PLAN.md` §3의 두 항목을
같이 담게 됐다 — **AGENTS.md 규칙 11(1 PR = 1 기능) 위반이다.**
로그인 폼 없이 슬라이드만 만들면 빈 패널이 남아 나눌 수가 없었다.

외부 배경 이미지, `scale(0.95)`(§1은 98%), `text-transform: uppercase`(한국어에 무의미).

# 0011. 프로필은 `/u/[username]`에 두고, 팔로우 목록은 그 아래 자기 라우트로 편다

- 상태: 확정
- 날짜: 2026-09-12

## 맥락

팔로우를 걸 자리가 필요했다. 글과 댓글에 이름이 이미 붙어 있으므로(`components/ui/ContentCard.tsx`)
이름을 눌러 가는 화면이 그 자리다. 그 화면에서 팔로워 · 팔로잉 수를 보여주고,
수를 누르면 목록이 열린다.

## 선택지

### 주소 모양

**A. `/u/[username]`** — 이름공간을 하나 둔다

- 기존 라우트가 전부 `/post/[id]`, `/comment/[id]`처럼 앞에 무엇인지를 달고 있다
- `/login` · `/signup`과 절대 겹치지 않는다

**B. `/[username]`** — 트위터식으로 루트에 바로 놓는다

- 주소가 짧고 사람이 외우기 쉽다
- 루트에 동적 세그먼트가 생겨 `/login`, `/signup`과 같은 자리를 다툰다.
  Next가 정적 세그먼트를 먼저 맞추므로 지금은 돌아가지만, 앞으로 추가되는 화면마다
  "이 이름을 별명으로 못 쓰게 막았나"를 확인해야 한다.
  그 확인은 `profiles_username_format`(`supabase/migrations/0001_init.sql:20`)이
  아니라 사람이 하게 된다

### 팔로워 · 팔로잉 목록을 어디에 두나

**C. 프로필 화면 안의 탭** — 한 화면에서 전환한다

- 주소가 하나라 공유하면 늘 첫 탭이 열린다
- 탭은 포커스와 키보드를 직접 다뤄야 해서 shadcn에서 가져와야 한다
  (`AGENTS.md` 스타일 절). 지금 레포에 Tabs가 없다

**D. `/u/[username]/followers`와 `/u/[username]/following`** — 각자 라우트

- 주소가 목록을 가리킨다. 뒤로 가기가 그대로 동작한다
- 윗 폴더의 `loading.tsx` · `not-found.tsx`가 두 화면을 같이 덮는다 (규칙 10)
- 화면 파일이 둘로 늘어난다. 다른 것은 어느 쪽을 읽느냐와 제목뿐이다

### 토글의 의도를 누가 정하나

**E. 서버가 현재 상태를 다시 읽어 뒤집는다** — 진짜 토글

- 클라이언트가 무엇을 보내든 결과가 "반대쪽"이다
- 읽고 쓰는 사이에 다른 탭이 눌리면 둘이 서로를 지운다. 읽은 값은 쓰는 순간 이미 낡았다

**F. 버튼이 보고 있던 상태를 의도로 보낸다** — `intent=follow|unfollow`

- 같은 의도가 겹쳐도 결과가 같다. 기본키 중복(23505)은 이미 팔로우 중이라는 뜻이고,
  없는 행을 지우는 것은 이미 푼 상태라는 뜻이다. 둘 다 원하던 결과다
- 화면이 낡은 상태를 들고 있으면 한 번은 헛손질이 된다. 다음 `refresh`가 바로잡는다

## 결정

**A, D, F.**

A는 이 레포의 기존 주소 규칙을 그대로 따른 것이고, 루트를 비워두면 나중에 무엇을 놓든
별명과 다투지 않는다. D는 탭을 새로 가져오지 않아도 되고 상태 네 가지가 폴더 하나로 덮인다.
F는 동시에 눌렸을 때 서로를 지우지 않는다.

## 따라온 것

- 마이그레이션이 없다. `follows` 테이블과 RLS 세 정책은 `0001_init.sql:96-113`,
  `225-237`에 이미 있고, `types/database.ts`에도 이미 생성돼 있다
- 자기 자신을 팔로우하는 것은 앱에서 세지 않는다. `follows_no_self` 제약이 DB에서
  막는다 (규칙 9). 화면은 자기 프로필에서 버튼을 아예 세우지 않는다
- 팔로워 · 팔로잉 수를 `follows!follows_following_id_fkey(count)`로 DB에서 센다.
  `follows`가 `profiles`를 두 번 참조해서 임베드에 FK 이름을 줘야 하고, 그 이름의
  출처는 `types/database.ts`의 `Relationships`다. 결정 0008이 자기 참조 임베드에서
  PGRST200으로 거절당한 적이 있어 세 쿼리를 원격 DB에 그대로 던져 확인했다 —
  집계는 `followers: [{count: 0}]`, 조인은 `{user: {...}}` 모양으로 돌아온다
- 목록 줄에는 팔로우 버튼을 두지 않는다. 팔로우는 프로필 화면 한 곳에서 한다.
  목록마다 버튼을 세우면 같은 동작이 두 곳에 생긴다 (규칙 2)
- `SideNav`가 클라이언트 컴포넌트가 됐다. 지금 어디인지를 `usePathname`으로 직접
  읽는다. 화면마다 prop으로 내려주면 라우트가 늘 때마다 호출부를 전부 고쳐야 한다
- 프로필 화면에 **그 사람이 쓴 글은 없다.** 요청 범위 밖이라 자리를 만들지 않았다

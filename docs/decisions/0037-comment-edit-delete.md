# 0037. 내 댓글과 답글도 더보기 메뉴에서 수정하고 지운다

- 상태: 확정
- 날짜: 2026-09-14
- 대체: [0022](0022-post-edit-delete.md)의 "댓글은 범위 밖으로 둔다"

## 맥락

사용자가 댓글도 수정과 삭제를 요청했다. 스키마에는 이미 자리가 있다. "본인 댓글만 수정한다",
"본인 댓글만 지운다"(`supabase/migrations/0001_init.sql`)가 처음부터 있었고, 수정으로 스레드 위치를
옮기는 것은 트리거가 막는다(`0002_comments_immutable_thread.sql`). 마이그레이션을 더하지 않는다.

## 선택지

### 메뉴 컴포넌트

**A. `PostMenu`를 복사해 `components/comment/CommentMenu.tsx`를 만든다**

- 게시글 쪽을 건드리지 않는다
- 드롭다운, 수정 모달, 확인 모달이 같은 모양으로 두 벌이 된다. 규칙 2 위반이다

**B. `PostMenu`를 `components/ui/ContentMenu.tsx`로 올리고 무엇을 고치고 지우는지를 설정으로 받는다**

- 한 벌이다. 게시글은 `POST_MENU`(`components/post/post-compose.ts`), 댓글은 `COMMENT_MENU`, `REPLY_MENU`
  (`components/comment/comment-menu.ts`)가 액션, 폼 필드 이름, 문구를 채운다
- ui 컴포넌트가 액션을 import하지 않고 props로 받는다

### 답글 화면에서 주인공 댓글을 지웠을 때

**C. 그 자리에 404가 뜬다.** 결정 0022의 게시글 상세와 같다

**D. 게시글 화면으로 돌려보낸다.** 액션이 어느 화면에서 불렸는지 알아야 해서 값을 하나 더 실어야 한다

## 결정

**B와 C.**

B는 두 번째 기능이 같은 모양을 쓰기 시작한 시점이라 규칙 2대로 올린다. 옛 자리 `components/post/PostMenu.tsx`는 지웠다.

C는 0022와 같은 이유다. 지운 것이 사라진 자리에 서 있다는 것은 사실이고, 불편하다는 말이 나오면 D를 더한다.

## 따라온 것

- 내 것인지는 게시글처럼 작성자 id와 보는 사람 id로 가린다. 메뉴는 친절함이고 방어는 RLS다 (규칙 9)
- 최상위 댓글의 확인 모달은 "달린 답글도 함께 삭제됩니다."라고 말한다. 외래키 cascade다(`0001_init.sql:79`)
- 수정은 본문만 보낸다. 검증은 서비스 zod(`COMMENT_CONTENT_MAX`)이고, 남의 댓글이면 0행을 문구로 바꾼다

## 비용

- 수정됐다는 표시가 없다. 게시글도 없다. `updated_at` 컬럼이 없어 표시하려면 마이그레이션이 필요하다

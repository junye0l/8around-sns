# 0028. 왼쪽 레일을 레이아웃으로 올리고, 프로필에 걸린 두 줄만 기다린다

- 상태: 확정
- 날짜: 2026-09-14
- 대체: [0015](0015-threads-shell.md)의 "`PageShell`의 `nav`가 선택이 됐고 `loading.tsx`가 가짜 레일을 안 세운다"

## 맥락

레일(`components/layout/SideNav.tsx`)을 화면 일곱 곳의 `page.tsx`가 `PageShell`의 `nav`로 넘기고 있었다.
`loading.tsx`는 레일을 넘기지 않으므로 화면을 옮길 때마다 레일 전체가 사라졌다가 데이터가 오면 다시 나타났다.
사용자가 사이드바의 로딩 처리 방식을 물었고, 레일을 유지하는 쪽으로 가기로 했다.

Next 레이아웃은 화면을 옮겨도 다시 그려지지 않는다
(`node_modules/next/dist/docs/01-app/01-getting-started/03-layouts-and-pages.md:43`).
`login`, `signup`, 루트 `not-found`에는 레일이 없으므로 루트 레이아웃에는 둘 수 없다.
레일이 있는 화면을 `app/(main)/` 라우트 그룹으로 묶고 그 `layout.tsx`에 둔다. 주소는 바뀌지 않는다.

레일에서 글쓰기와 프로필 두 줄만 로그인한 사람의 프로필이 있어야 선다.

## 선택지

**A. 레이아웃이 프로필을 기다린 뒤 레일을 한 번에 그린다**

- 가장 단순하다
- 레이아웃이 기다리는 동안 그 아래 `loading.tsx`도 막혀서 새로고침 때 스켈레톤이 늦게 뜬다

**B. 고정 항목은 바로 그리고, 두 줄만 `Suspense`로 기다린다**

- 새로고침 때도 레일과 스켈레톤이 바로 뜬다
- 기다리는 두 자리에 같은 크기(`size-12`) 빈칸을 두어, 가운데 정렬된 다른 아이콘이 움직이지 않는다
- 레이아웃이 Promise를 넘기고 `SideNav`가 `use`로 푼다. 경계 두 개가 늘어난다

## 결정

**B.**

같이 정한 값:

- **팔로워, 팔로잉 목록은 `getCurrentProfile`을 부르지 않는다.** 레일에만 쓰던 조회였다
- **추천, 팔로잉, 게시글, 답글, 프로필은 여전히 `getCurrentProfile`을 부른다.** 내 글 표시, 아바타 이름, 팔로우 버튼에 쓴다.
  새로고침 때만 레이아웃과 겹쳐 두 번 조회한다. 화면을 옮길 때는 레이아웃이 다시 돌지 않는다
- **그룹 안의 `not-found.tsx`에도 레일이 보인다.** 루트 `app/not-found.tsx`는 그룹 밖이라 레일이 없다

## 비용

- 레이아웃은 화면을 옮길 때 다시 돌지 않으므로 로그인 확인을 여기에 두면 안 된다
  (`node_modules/next/dist/docs/01-app/02-guides/authentication.md:1352`). 미들웨어와 각 화면이 계속 맡는다
- 프로필 조회가 비면(세션은 있는데 `profiles`가 없음) 빈칸이 사라지며 아래 아이콘이 한 칸 올라온다. 드문 경우라 두었다
- 화면 폴더가 `app/(main)/` 아래로 한 단 내려간다

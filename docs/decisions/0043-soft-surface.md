# 0043. 디자인을 소프트 서피스로 바꾸고 토큰의 출처를 우리 문서로 옮긴다

- 상태: 확정
- 날짜: 2026-09-14
- 대체: [0009](0009-toss-tds-tokens.md), [0015](0015-threads-shell.md), [0035](0035-rail-blur.md) 전체.
  [0012](0012-a11y-pass.md)의 남은 칸 둘, [0014](0014-composer-layout.md)의 "버튼 60x36", [0033](0033-responsive-shell.md)의 "768px 하나로 나눈다",
  [0034](0034-auth-responsive.md)의 모바일 로고 가운데 정렬, [0039](0039-interest-chip-edge.md)의 칩 정렬

## 맥락

사용자가 impeccable 스킬로 전 화면을 점검한 뒤 디자인 자체의 리뉴얼을 요청했다.
점검에서 나온 문제 중 절반이 토큰에서 왔다. 보조 글자 `#8b95a1`이 흰 바탕에서 3.04:1로 AA에 못 미쳤고,
결정 0012가 이 값을 남은 칸으로 남겨두었다. 흑백 버튼과 아이콘만 있는 레일은 처음 온 사람에게
누를 곳과 현재 위치를 잘 알려주지 못했다.

`docs/DESIGN.md`는 Toss 공개 자료를 옮긴 레퍼런스라 "우리 제품의 값"을 정할 권한이 없었다.
화면을 바꿀 때마다 "문서에 없는 값"이 로컬 확장으로 쌓였다.

## 선택지

**1회차. 은유를 입힌 세 방향** (impeccable의 방향 추첨)

- A. 지하철 노선도. 관심사가 노선, 사람이 환승역
- B. 동아리 모집 전단 게시판. 글이 관심사 색 종이, 뜯는 탭이 반응
- C. OTT 편성표. 관심사마다 가로 줄, 글이 타일

사용자가 셋 다 거절하고 "모던하고 깔끔한 디자인"을 지정했다.

**2회차. 모던하고 깔끔한 세 방향**

- D. 크리스프 모노. 흰 바탕, 1px 선, 검정 하나 (Vercel, Linear). 밀도가 높고 다크 유지가 싸지만 개성이 약하고 차갑다
- E. 소프트 서피스. 옅은 바탕에 둥근 흰 면, 보라 하나 (Bluesky, iOS). 친근하고 터치 영역이 넉넉하지만 한 화면의 글 수가 적다
- F. 볼드 타이포. 큰 굵은 글자와 코랄 하나 (토스 큰 글자 화면, Airbnb). 짧은 글이 돋보이지만 긴 글이 화면을 빨리 채운다

**현재 방향을 다듬기** (G). Threads식 흑백을 유지하고 크리틱 목록만 고친다. 토큰 대비 문제는 남는다.

## 결정

**E.** 사용자가 골랐다.

같이 정한 것

- `docs/DESIGN.md`를 레퍼런스 문서에서 우리 제품의 디자인 문서로 바꾼다. 값의 출처가 여기가 된다
- 토큰 이름은 지금 것(`background`, `canvas`, `fg`, `fg-muted`, `hairline`, `primary`, `danger`, `scrim`)을 살린다.
  화면 코드의 클래스 이름이 덜 바뀐다. 새로 `canvas-raised`, `fill`, `fg-disabled`, `primary-fill`, `primary-soft`,
  `on-primary-soft`, `danger-soft`를 둔다
- `primary`는 포커스 링 전용에서 동작 색으로 넓어진다. 포커스 링은 계속 `primary`다 (결정 0010 유지)
- 그림자를 라이트에서만 둘 쓴다. 다크는 면 색으로 나눈다
- 관심사와 사진 없는 아바타는 글자 해시로 여섯 톤 중 하나를 고른다. 관심사가 자유 입력이라 고정 분류가 없다
- 소개는 아바타 옆이 아니라 이름 아래 전체 폭에 둔다. 요약 카드는 3줄에서 자른다. 사용자가 긴 소개의 가독성을 짚었다
- 한글은 단어 단위로 줄바꿈한다(`break-keep`)
- 뼈대는 768, 1024, 1280px 세 경계로 나눈다. 레일은 펼치지 않고 늘 라벨을 보인다. 그래서 0035의 흐림이 필요 없다
- 모바일 인증 화면의 로고는 왼쪽 정렬로 큰 제목 위에 둔다. 건너가는 줄의 바닥 자리는 0034 그대로다
- 댓글 쓰기는 0019대로 시트에서 한다. 화면 아래 입력줄은 시트를 여는 줄이다
- 글쓰기 입력칸 높이 고정과 카운터 없음은 0014 그대로다
- 글쓰기 보내기 버튼은 0014의 60x36 고정 대신 다른 작은 버튼과 같은 `sm`(높이 32px, 글자 폭)이다.
  버튼 규격을 하나로 모은다. 로딩 중 폭은 스피너가 글자 자리를 지켜 유지한다
- 빈 입력이면 보내기 버튼을 끄는 것은 [결정 0042](0042-submit-guard.md)가 정했다. 여기서는 꺼진 모양만 정한다.
  0014가 비활성을 피한 이유였던 비활성 글자 대비 2.47:1은 `fg-disabled`를 WCAG 비활성 예외로 따로 둬서 사라졌다

## 비용

- 모든 화면이 바뀐다. `docs/PLAN.md`의 리뉴얼 절이 PR 여섯 개로 나눈다
- 시스템 글꼴이라 운영체제마다 한글 모양이 다르다
- 카드가 면을 차지해 한 화면의 글이 전보다 적다
- `primary`의 뜻이 넓어져, 전에 "파랑은 동작에만"을 전제로 쓴 코드 주석(`app/globals.css`, `components/ui/Button.tsx` 등)이
  리뉴얼 1단계 전까지 사실과 다르다

## 남은 칸

- **웹폰트.** 시스템 글꼴 그대로 둘지, Pretendard(OFL)를 직접 호스팅할지. 정하기 전까지 시스템 글꼴이다
- **"추천" 이름.** 실제 정렬이 최신순(`lib/queries/post.ts`의 `listFeed`)인데 이름을 유지할지
- **글쓰기 취소 확인.** 쓰던 글이 있을 때 시트를 닫으면 버릴지 물을지

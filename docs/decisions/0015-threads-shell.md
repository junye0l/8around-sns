# 0015. 화면 뼈대를 Threads 모양으로 바꾸고 버튼을 흑백으로 옮긴다

- 상태: 대체됨 → [0028](0028-sidenav-in-layout.md), [0033](0033-responsive-shell.md), [0041](0041-soft-surface.md)
- 날짜: 2026-09-12

## 맥락

사용자가 "Threads와 비슷한 디자인으로 UI별로 개선"을 요청했다. 결정 0013이 이미 레일
구성을 Threads에서 가져왔지만 모양은 Toss 문서의 파랑 버튼과 240px 글자 레일이었다.

Threads의 뼈대는 셋이다. 배경 위에 아이콘만 있는 얇은 레일, 가운데 흰 카드 컬럼(윗모서리만
둥글고 바닥까지 이어진다), 검정 채움 버튼. 색 토큰은 `docs/DESIGN.md`의 중립색으로 다
채워지지만, 기하 값 몇 개와 버튼 색은 문서에 없거나 문서와 다르다.

`docs/DESIGN.md`의 Application priority는 "1. Direct user instructions"를 맨 위에 둔다.
그래서 지시가 규칙 3보다 앞선다. 다만 무엇을 지어냈는지는 여기 남긴다.

## 선택지

**A. 토큰은 그대로 두고 배치만 바꾼다** — 파랑 버튼, 흰 레일

- `globals.css`를 안 건드린다
- 파랑 채움 버튼과 검정 레일 아이콘이 한 화면에 서면 Threads가 아니라 Toss에 Threads
  배치를 입힌 것이 된다. 요청과 어긋난다

**B. 배치와 버튼 색을 같이 바꾸고, 파랑은 포커스 링에만 남긴다**

- Threads와 같은 흑백 인상이 난다
- `--color-primary-hover`가 갈 곳을 잃는다. 하네스가 안 쓰는 색 토큰을 잡으므로 지운다
- 결정 0010(포커스 링은 primary)은 그대로다. 검정 버튼 위에서 파랑 링이 더 잘 보인다

## 결정

**B.** 사용자가 Threads를 지정했다.

같이 정한 값:

- **레일 폭 76px(`w-19`), 항목 48px(`size-12`), 아이콘 24px(`size-6`).** 레퍼런스의
  아이콘 전용 레일 치수를 4px 그리드에 맞춘 값이다. 다른 아이콘은 `size-5`지만
  아이콘만 있는 레일에서는 20px이 너무 작다
- **카드 윗모서리 24px.** `--radius-xl`로 `app/globals.css`에 로컬 확장으로 적었다
- **버튼 모서리 10px(`--radius-lg`).** TDS medium 버튼 값이라 문서 안이다
- **기본 버튼 높이 40px.** 결정 0009의 남은 칸 "40 대 46"을 닫는다. Threads 버튼이
  36에서 40 사이고, 문서의 두 관측값 중 가까운 쪽이 40이다
- **outline 버튼 테두리는 `hairline`.** 이전의 `fg` 테두리는 검정 채움 옆에서 무게가 같아
  둘이 구분되지 않는다
- **hover와 pressed는 `bg-fg/90`, `bg-fg/80`.** 새 색을 만들지 않고 불투명도만 낮춘다.
  결정 0013이 오버레이에 쓴 방식과 같다
- **레일은 배경과 테두리가 없다.** 그래서 `PageShell`의 `nav`가 선택이 됐고 `loading.tsx`가
  가짜 레일을 안 세운다
- **카드는 `PageShell`이 그린다.** 일곱 화면이 같은 상자를 각자 세우고 있었다 (규칙 2)

## 비용

- 파랑이 화면에서 거의 사라진다. `AGENTS.md`의 "파랑은 동작에만"은 여전히 맞지만
  "동작"이 이제 포커스 링뿐이다
- 페이지 배경은 Toss `#f2f4f6`을 그대로 쓴다. Threads의 `#fafafa`보다 어둡다.
  문서에 없는 색을 지어내지 않는다
- 가로 최소 폭이 824px(`min-w-206`)이다. 레일이 양쪽 76px씩 자리를 잡아야 컬럼이
  화면 가운데에 온다. 좁은 폭 대응은 `docs/PLAN.md`가 뒤로 미뤄둔 그대로다

# 0026. 입력칸 라벨을 보이게 두고, 누르면 테두리 위로 올린다

- 상태: 확정
- 날짜: 2026-09-14
- 대체: [0016](0016-threads-auth.md)의 입력칸 값 두 개(채움, 감춘 라벨)

## 맥락

사용자가 인증 화면이 템플릿처럼 보인다고 했고, 가입 화면 개선안의 "입력칸 재해석"을 기준으로
로그인까지 고치고 입력칸을 누르면 라벨이 테두리로 올라가는 움직임을 달라고 지시했다.

결정 0016은 Threads를 따라 라벨을 `sr-only`로 감추고 placeholder가 그 말을 대신하게 했다.
두 가지가 어긋났다.

- 값을 채우면 placeholder가 사라져 어떤 칸인지 화면에서 알 수 없다
- 2026-09-13에 다시 연 Threads 로그인 입력칸은 회색 채움이 아니라 흰 채움에 테두리였다.
  0016이 옮긴 "채운 상자"의 전제가 레퍼런스에서 사라졌다

## 선택지

**A. 라벨을 상자 위에 따로 둔다**

- 움직임이 없다. 코드가 가장 단순하다
- 칸마다 한 줄이 늘어 가입 폼이 길어진다. 지시한 움직임이 없다

**B. 채운 상자 안 윗줄에 작은 라벨을 늘 둔다** (가입 개선안의 목업)

- 높이가 그대로다
- 라벨이 12px이라 문서 타입 스케일(최소 14px) 밖이다. 지시한 "테두리로 올라가는" 모양이 아니다

**C. 흰 상자에 라벨을 넣고, 누르거나 값이 차면 테두리 위로 올린다**

- 지시한 모양이다. 높이가 그대로고 라벨이 늘 보인다
- 라벨 뒤를 `canvas`로 칠해 테두리를 끊으므로 흰 바탕 위에서만 맞다. 인증 화면은 흰 바탕이다
- 뜨는지 여부를 `:placeholder-shown`으로 가르므로 예시 문구가 없는 칸에도 빈 칸 하나를 placeholder로 넣는다

## 결정

**C.** 사용자가 지정했다.

같이 정한 값:

- **상자는 `canvas` 채움, `fg-muted` 테두리, 포커스에 `fg` 테두리.** 흰 바탕에서 3.04:1로 결정 0012의 기준을 넘는다
- **라벨은 비었을 때 `text-body` 칸 가운데, 올라가면 `text-body-sm`.** 둘 다 문서 스케일 안이다
- **움직임은 `--motion-fast`와 `--ease-standard`.** 새 이징을 만들지 않는다. reduce 환경에서는 토큰이 0ms로 떨어진다
- **예시 문구는 라벨이 올라간 뒤에만 보인다.** 올라가기 전에는 라벨과 같은 자리라 겹친다
- **비밀번호 칸에 보기 토글을 붙인다.** 개선안 C에 들어 있었고 로그인과 가입이 같이 받는다

개선안 C에 있던 별명 칸의 `@` 접두와 비밀번호 규칙 실시간 체크는 이번에 넣지 않았다.
라벨 움직임과 따로 되돌릴 수 있는 기능이라 나눈다.

## 비용

- `TextField`가 토글 상태를 가지게 되어 클라이언트 컴포넌트가 됐다. 부르는 곳이 이미 둘 다 클라이언트 폼이라 번들 경계는 그대로다
- Chrome 자동완성이 칸을 옅은 파랑으로 칠하면 올라간 라벨 뒤의 흰 면이 도드라질 수 있다. 확인하지 못했다

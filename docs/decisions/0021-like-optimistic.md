# 0021. 좋아요는 누르는 즉시 반영한다

- 상태: 확정
- 날짜: 2026-09-12

## 맥락

[결정 0020](0020-post-likes.md)은 상태를 서버에만 두고, 액션이 끝나고 화면이 다시
그려질 때 하트가 채워지게 했다. `FollowButton`이 쓰던 방식 그대로다.

문제는 그 사이의 빈 시간이다. 좋아요는 한 화면에서 여러 번, 빠르게 누르는 동작인데
누른 뒤 아무 일도 일어나지 않는 구간이 있으면 안 눌린 줄 알고 다시 누른다.
팔로우는 화면당 한 번 누르는 동작이라 같은 문제가 없었다.

사용자가 낙관적 업데이트를 요청했다. `docs/PLAN.md`에도 열린 항목으로 있었다.

## 선택지

**A. 서버 왕복 뒤 반영한다** — 결정 0020 그대로

- 화면에 뜨는 값이 항상 DB의 값이다. 거짓을 보여줄 일이 없다
- 누르고 나서 반응까지 왕복 한 번이 비어 있다

**B. `useOptimistic`으로 먼저 바꾸고 서버 응답으로 확정한다**

- 반응이 즉시다. 실패하면 서버가 준 값으로 되돌아온다
- 실패한 순간 화면이 한 번 되돌아가는 것을 사용자가 본다. 문구로 이유를 말해야 한다

**C. 클라이언트 상태로 들고 간다** — 서버 값은 첫 렌더에만 쓴다

- 왕복이 아예 안 보인다
- 다른 화면에서 바뀐 값이 반영되지 않는다. 같은 글이 피드와 상세에서 다르게 보인다

## 결정

**B.** 사용자가 지정했고, 되돌릴 자리가 분명하다.

React 19의 `useOptimistic`이 액션이 끝날 때까지만 앞선 값을 들고 있다가 서버가 준
props로 돌아간다. 성공하면 `refresh`가 이미 같은 값을 가져오므로 화면이 흔들리지 않고,
실패하면 그 자리에서 되돌아오면서 문구가 뜬다.

## 따라온 것

- **`aria-busy`와 진행 중 표시를 뺐다.** 결정 0020이 포커스를 지키려고 `disabled`
  대신 쓰던 것인데, 이제 누른 즉시 결과가 보이므로 "진행 중"이라고 말할 상태가 없다.
  버튼은 여전히 `disabled`가 되지 않아 포커스가 유지된다
- **중복 클릭 가드도 뺐다.** 빠르게 두 번 누르면 두 요청이 나가지만 각각 멱등이고
  마지막 것이 이긴다. DB에 행은 하나다(기본키). 가드가 막던 것은 화면 깜빡임인데
  그 깜빡임 자체가 없어졌다
- **누를 때 한 번 튄다.** `--animate-like-pop`을 `app/globals.css`에 로컬 확장으로
  적었다. 길이는 `--motion-fast`, 이징은 `--ease-standard`로 기존 토큰만 쓴다.
  1.2배까지 커졌다 제자리로 오는 한 번짜리 움직임이라 스프링도 오버슈트도 아니다.
  화면에 뜰 때가 아니라 누른 뒤에만 건다 — 안 그러면 이미 누른 글이 목록에 뜰 때마다 튄다
- **0을 보인다.** 옆의 댓글 수가 [PR #41](https://github.com/junye0l/8around-sns/pull/41)에서
  같은 규칙으로 바뀌었다. 한 줄에 선 두 숫자가 서로 다른 규칙을 쓰고 있었다
- **팔로우 버튼은 그대로다.** 같은 문제가 없다. 계획서의 낙관적 업데이트 항목에
  팔로우와 댓글이 남아 있다

# 0049. E2E 확인은 CI 결과로 하고, 로컬 실행은 CI 실패를 재현할 때만 쓴다

- 상태: 확정
- 날짜: 2026-09-15
- 대체: [0048](0048-e2e-against-remote-db.md)의 "로컬 실행은 원격 DB에 대고 돈다"를 기본 확인 절차로 두던 것

## 맥락

0048은 로컬 E2E를 원격 DB에 대고 돌리고 글과 팔로우만 지우기로 했다. 계정은 지울 권한이 없어 한 번 돌 때마다 빈 계정 둘이 남는다.
그런데 AGENTS.md 규칙 17과 `/pr` 스킬은 흐름을 바꿀 때마다 로컬에서 `npm run test:e2e`를 돌리라고 했다.
규칙을 지킬수록 실제 DB에 계정이 쌓인다. 규칙이 생긴 날에만 6개가 남았다.

한편 CI의 `e2e` job은 러너 안에 띄운 로컬 Supabase에 대고 돌아 아무것도 남기지 않는다(`.github/workflows/ci.yml`). main에서 통과했다.

## 선택지

**A. 로컬에서도 Docker로 Supabase를 띄워 돌린다**
- 계정이 남지 않는다. CI와 같은 설정이라 위험이 낮다
- 개발자 컴퓨터에 Docker Desktop이 떠 있어야 하고, 첫 실행에 Supabase 이미지를 받는다. 실행마다 시작 시간이 1~2분 더해진다
- 스크립트, 결정, 문서 수정이 PR 하나 규모다

**B. 확인은 CI 결과로 하고, 로컬 실행은 기본 절차에서 뺀다**
- 코드가 없다. 규칙 17과 `/pr` 스킬의 문장만 바뀐다
- 결과를 보려면 푸시하고 CI를 기다린다

## 결정

**B.** 사용자가 골랐다. A는 README의 개선할 부분에 남긴다.

- 로컬 `npm run test:e2e`는 없애지 않는다. CI 실패를 손으로 재현할 때 쓴다
- 0048의 정리 방식(`finally`에서 글과 팔로우 삭제, 동작 제한 15초)은 그대로다

## 비용

- 흐름을 고치면 결과를 보기까지 푸시 후 약 3분(CI `e2e` job 실측)을 기다린다
- 푸시마다 Vercel 프리뷰 배포가 하나씩 소모된다
- 누가 로컬에서 돌리면 여전히 계정이 남는다
- 이미 남은 테스트 계정 6개는 Supabase 대시보드에서 사람이 지워야 한다

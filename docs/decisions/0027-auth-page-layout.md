# 0027. 인증 화면을 왼쪽 정렬로 바꾸고, 건너가는 줄을 버튼으로 둔다

- 상태: 일부 대체됨 → [0034](0034-auth-responsive.md)
- 날짜: 2026-09-14
- 대체: [0016](0016-threads-auth.md)의 "아래 가입하기 링크 한 줄"

## 맥락

사용자가 입력칸 말고 가입, 로그인 화면의 나머지가 AI가 만든 템플릿처럼 보인다고 했고, 쓸데없는 장식 없이
고치라고 지시했다. 390px과 1280px에서 연 화면에서 본 것은 이렇다.

- 제목, 폼, 건너가는 줄이 전부 가운데 정렬이다. 추천, 프로필, 404는 모두 왼쪽 정렬이다
- 제목이 `text-body`(16px)라 입력칸 라벨(16px)과 크기가 같다. 위계가 없다
- "8around 계정으로 로그인"은 다른 계정 종류가 없는데 "계정으로"를 붙인다. Threads 문구를 옮긴 흔적이다
- 로고가 없다. 로그인하면 왼쪽 위에 "8"이 나타나 같은 앱으로 이어지지 않는다
- "처음 오셨나요? 가입하기" 밑줄 링크는 누를 자리가 글자 높이 21px뿐이다
- 56px 버튼 안 글자가 14px이다. `docs/DESIGN.md` TDS xlarge 버튼은 17px/600이다
- 로그인은 에러 문구 자리 24px이 칸과 버튼 사이에 따로 떠서 빈 틈이 56px이다. 가입은 폼 에러를 제목 아래에 띄워 둘의 자리가 다르다

## 선택지

**A. 가운데 정렬은 두고 크기와 간격만 고친다**

- 변경이 가장 적다. Threads 로그인 화면과 가장 가깝다
- 가운데 정렬과 밑줄 링크 줄이 그대로라 사용자가 짚은 인상이 남는다

**B. 왼쪽 정렬로 바꾸고, 건너가는 줄을 선 아래 문구와 outline 버튼 한 줄로 둔다**

- 추천의 글쓰기 줄(`components/ui/ComposeRow.tsx`, 왼쪽 문구와 오른쪽 outline 버튼, `hairline` 선)과 같은 모양이라
  새 모양을 만들지 않는다. 버튼이라 누를 자리가 40px이고 hover, pressed, focus 상태를 `Button`에서 그대로 받는다
- 로고를 왼쪽 레일과 같은 자리에 둔다. 새 장식이 아니라 로그인 뒤에도 같은 자리에 있는 것이다
- Threads 배치에서 멀어진다

## 결정

**B.**

같이 정한 값:

- **제목은 `text-title`(24px/700), 왼쪽 정렬, 문구는 "로그인"과 "가입".** 라우트 제목과 같다. 부제는 두지 않는다
- **로고는 `BrandMark`로 빼서 `SideNav`와 같이 쓴다.** 규칙 2에 따라 두 번째 화면이 쓰기 시작해 `components/ui/`로 올렸다
- **제출 버튼 글자는 `text-body`(16px).** TDS xlarge 17px에 가장 가까운 토큰이다
- **폼에 묶인 문구는 버튼 바로 위.** 로그인은 비밀번호 칸에 `gap-1`로 붙여 가입 폼의 안내 줄과 같은 간격이고, 가입의 폼 에러도 제목 아래에서 버튼 위로 옮겼다
- **건너가는 줄의 문구는 그대로다.** "처음 오셨나요?", "이미 계정이 있나요?"

## 비용

- 결정 0016이 따른 Threads 배치 중 가운데 정렬과 링크 줄을 버린다
- 가입의 폼 에러(시도가 잦을 때 등)가 뜨면 버튼이 한 줄 밀린다. 로그인처럼 자리를 늘 잡아두면 드문 문구 때문에 가입 폼에 빈 틈이 생겨 잡지 않았다

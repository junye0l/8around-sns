# 결정 기록

갈림길에서 무엇을 고르고 **무엇을 버렸는지** 적는다. 코드는 고른 것만 보여주므로,
버린 선택지와 그 이유는 여기에만 남는다. 없으면 같은 논의를 몇 달 뒤에 다시 한다.

## 무엇을 적나

- **선택지가 둘 이상이었고**, 어느 쪽을 골라도 코드가 돌아갔던 것
- 되돌리려면 비용이 드는 것 — 스키마, 인증 방식, 보안 판단
- 규칙을 일부러 어긴 것과 그 값

관례적인 기본값이 명확했던 선택은 적지 않는다. 코드 주석 한 줄로 끝나는 것도 적지 않는다.
(예: "에러 문자열을 파싱하지 않고 DB 상태로 판정한다" → `lib/services/auth.ts` 주석)

**아직 정하지 못한 값은 그 기록의 맨 끝 `## 남은 칸`에 적는다.** 결정을 내리다 보면 같이 걸리는데
답이 없는 값이 나온다 — 그것만 모아두는 자리다. 채워지면 그 줄을 지우고 새 번호로 결정을 쓴다.
미정 값의 목록은 여기 말고 어디에도 두지 않는다 (규칙 3).

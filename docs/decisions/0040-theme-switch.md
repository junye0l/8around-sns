# 0040. 테마는 쿠키에 두고 색 토큰을 light-dark()로 적는다

- 상태: 확정
- 날짜: 2026-09-14

## 맥락

사용자가 다크 모드를 요청했다. 더 보기 메뉴의 디자인 항목에서 다크, 라이트, 시스템 중 하나를 고르고,
기본값은 시스템이며, 새로고침하거나 브라우저를 닫았다 열어도 고른 값이 남아야 한다.

그전까지 `AGENTS.md` 스타일 절은 라이트 모드만 지원한다고 적었다. 화면 코드는 `bg-canvas`, `text-fg` 같은
토큰 이름만 쓰고 hex를 직접 쓰지 않으므로 토큰 값만 테마마다 바꾸면 된다.

## 선택지

**어디에 남기나**

- A. 쿠키. 서버가 `app/layout.tsx`에서 읽어 `<html data-theme>`을 처음부터 박는다. 번쩍임이 없고 스크립트가 필요 없다.
  대신 루트 레이아웃이 `cookies()`를 읽어 모든 라우트가 동적 렌더링이 된다
- B. localStorage. 정적 렌더링을 지키지만, 칠하기 전에 읽으려면 `<head>`에 인라인 스크립트를 넣고
  `<html>`에 `suppressHydrationWarning`을 달아야 한다. 서버는 값을 모른다

**토큰을 어떻게 적나**

- C. `light-dark(라이트, 다크)`. 토큰 하나에 값 둘이 한 줄에 있다. `color-scheme`이 어느 쪽인지 고른다.
  스크롤바와 기본 입력칸도 같이 바뀐다
- D. `:root`와 `[data-theme=dark]`, `@media (prefers-color-scheme: dark)` 세 블록에 나눠 적는다.
  시스템과 다크가 같은 값을 두 번 적게 된다 (규칙 3)

## 결정

**A와 C.**

- 고른 값은 `theme` 쿠키에 1년 둔다. 시스템을 고르면 쿠키를 지운다. 쓰기는 `lib/actions/theme.ts`의 Server Action이다
- 메뉴는 누르는 즉시 `data-theme`을 바꾸고, 쿠키는 액션이 뒤따라 남긴다
- 다크 값은 `docs/DESIGN.md`에 없다. `app/globals.css`에 로컬 확장으로 적는다

| 토큰 | 라이트 | 다크 |
|---|---|---|
| canvas | #ffffff | #17171c |
| background | #f2f4f6 | #101013 |
| fg | #191f28 | #f2f4f6 |
| fg-muted | #8b95a1 | 같음 |
| hairline | #e5e8eb | #2c2c35 |
| danger | #e42939 | #f04452 |
| primary | #3182f6 | 같음 |

## 이유

로그인 뒤 화면은 이미 세션 쿠키를 읽어 동적이다. 동적 렌더링 비용은 로그인과 가입 두 화면에만 새로 생기고,
그 대가로 인라인 스크립트와 수화 경고 억제를 들이지 않는다.

## 비용

- 로그인, 가입 화면도 요청마다 서버에서 그린다
- 다크 값은 레퍼런스 근거가 없다. Toss 문서가 다크 팔레트를 주면 그 값으로 바꾼다
- `light-dark()`를 모르는 오래된 브라우저(크롬 123, 사파리 17.5 미만)에서는 색 토큰이 비어 보인다

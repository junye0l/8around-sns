# 0005. 머지는 머지 커밋으로 한다

- 상태: 확정
- 날짜: 2026-09-11

## 맥락

`AGENTS.md`에는 "머지는 squash"라고 적혀 있었는데, 실제로는 PR #2 · #3 · #4가 전부
머지 커밋으로 들어갔다. 문서와 실제가 어긋난 상태였다 — 규칙 3 위반이다.

```
$ git log --oneline --graph origin/main
*   28be42d Merge pull request #4 from junye0l/feat/auth-signup
|\
| * d5084e1 fix: Button이 자기 너비를 정하지 않게 한다
| * 67cfadd docs: 결정 기록 폴더와 규칙 14 추가
| * 8af0e21 feat: 가입·로그인 화면과 서버 액션 추가
| * 6967d75 chore: zod 추가와 vitest 경로 별칭 설정
|/
```

이미 푸시된 히스토리는 되돌리지 않는다("히스토리를 다시 쓰지 않는다" 절).
앞으로 어느 쪽으로 갈지만 정하면 됐다.

## 선택지

**A. squash (문서에 적혀 있던 것)**
- `main`을 훑으면 기능 목록이 그대로 보인다. 한 기능 한 줄
- 브랜치에서 되돌릴 수 있는 단위로 나눠둔 커밋이 하나로 합쳐진다.
  되돌릴 때 기능 전체를 되돌려야 한다

**B. 머지 커밋 (실제로 하고 있던 것)**
- 나눠둔 커밋이 `main`에 그대로 남는다. 문제가 된 커밋 하나만 revert할 수 있다
- `main`이 길어지고 그래프가 갈라진다

## 결정

**B.** 레포 설정에서 `Allow merge commits`만 켜고 squash·rebase는 끈다.

## 이유

커밋을 "되돌릴 수 있는 단위"로 나누라고 `AGENTS.md`가 요구한다. squash는 그 단위를
머지 시점에 지운다 — 나눈 값이 `main`에 도착하지 못한다.

실제로 PR #4는 의존성 추가 · 기능 · 문서 세 성격을 커밋 셋으로 나눴다. 나중에 zod 도입만
되돌리고 싶어지면 B에서는 `6967d75` 하나만 revert하면 되고, A에서는 방법이 없다.

설정으로 버튼을 하나만 남기는 이유는, 규칙을 기억에 의존하지 않게 하기 위해서다.
문서에만 적어두면 이번처럼 다시 어긋난다.

## 비용

`main` 히스토리가 길어지고 그래프가 갈라진다. 기능 단위로 훑기 어려워지는데,
그건 `git log --first-parent`로 보면 머지 커밋만 나열되어 한 기능 한 줄이 된다.
